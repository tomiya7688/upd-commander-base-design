# 「次」継続指示の引き継ぎ

更新日: 2026-11-08

## 目的

ユーザーの「次」「次へ」など同じ意味の継続指示を、常に「現在の目標に沿う設計または実装をキリのいい所まで進める」という実行指示として扱う。次の作業を自分で選び、検証可能な一区切りまで成果を作り、結果と未完了事項を報告する。確認だけで返答を終えない。

- `.claude/hooks/prompt_cloud.py`: 自動読み替え文を同じ方針へ更新。破壊的操作、課金、秘密/権限変更、必須レビュー/CI迂回の確認境界を維持。

## レビューで見つかり対応した点

Sourceryは、(1) 自動読み替えフックが旧完了条件を残していた点、(2) 複数セッションが同じマイルストーンを選ぶ可能性を指摘した。フックの指示を共通ルールに揃え、選択前に最新の共有状態を読み直すこと、共有進捗記録がある場合は着手前に担当単位を記録することを追記した。両スレッドは解決済みとして記録されている。

この変更は新しいロック機構や進捗データベースを追加していない。共有進捗記録が存在する場合に利用する方針である。

## 検証・レビュー状況

- ローカルの共通方針および指示ファイルに追加した対象ブロックは、Prettier 3.9.10で整形・check済み。
- PRの最新HEADに対するCodeRabbit再依頼はレート制限で完了しなかった。初回依頼の応答を最新HEADのレビュー証跡として扱わない。
- GitHubのcombined status APIは最新HEADに対してチェック項目なしを返した。必須CIが成功したとは扱わない。
- 残る必須ローカルレビュアー6者の個別実施証跡はない。Qwenは今回のクライアント検出で利用不可だった。その他は未実施として扱う。
- `.claude/hooks/prompt_cloud.py` のプロジェクト内変更に対するformat/check、構文確認、フック動作確認、テストは未実施。テストやCIの成功を主張しない。

## ローカル環境に関する注意

共通方針、Codex/Claudeのグローバル指示、Claudeのローカル自動読み替え文にも同じ意味を反映した。これらはこのリポジトリ外の設定であり、上記PRのファイルには含まれない。リポジトリ内のローカル `AGENTS.md` にも対象ルールがあるが、当時Git管理外だったためPRへ含めていない。

作業開始時に確認されたローカルcheckoutは、別ブランチ `security/221-attestation-verification` で複数の変更がdirtyだった。GitHubのmainを正本として最新を取得し、既存のdirty変更を保持してから作業すること。ユーザーは追加のworktreeフォルダーを作らず、Gitブランチを使う方針。

## 次に再開する場合

1. GitHubの最新mainを取得し、現在のcheckout・branch・dirty状態を確認する。既存変更をreset、clean、上書きしない。
2. この文書とPR #243の最新差分/レビュー履歴を照合する。
3. 必要なら対象ファイルだけformatter・構文/動作確認を行い、結果を実際のHEADと結び付けて記録する。
4. 新たな変更を公開する場合は新しいブランチとPRを使う。CodeRabbitの最新HEAD依頼、必須CI・承認、未解決の具体的指摘を確認する。利用不可や未応答は成功扱いせず根拠を残す。
5. 「次」は継続指示として受け取り、確認質問だけで止めず、現在の目標から次の設計/実装単位を選び、一区切りまで進める。
