# Architecture

**日本語** | [English](architecture.en.md)

この文書は、UPDを初めて読む人向けに、3層と3つの役割の関係を説明します。ひとつの機能をどの層へ置くかを例で確認し、続けて全体の考え方を紹介します。実装時に守る詳細な規則は[技術仕様の索引](../specification/README.md)を参照してください。

## 例: 商品を検索して一覧に表示する

検索画面でキーワードを入力し、商品情報を取得して一覧に表示する機能を考えます。ここでは「層」が仕事の種類を、「役割」がその層の中で担当する動きを表します。

| 層 | Commander（呼び出しを選ぶ） | Messenger（層間の要求・結果を運ぶ） | Processing（層に属する実作業） |
| --- | --- | --- | --- |
| UI | 検索操作の次に実行するUI側の処理を選ぶ | キーワードをProcessへ送り、検索結果を受け取る | 入力欄から値を読み、受け取った商品を画面用に整えて表示する |
| Process | 検索要求を検証やデータ取得へ振り分ける | UIからの要求を受け、Dataへの検索要求と結果を中継する | キーワードの妥当性を確かめ、検索条件や業務上の結果を決める |
| Data | どのデータ取得・保存処理を呼ぶか選ぶ | Processから検索要求を受け、取得結果を返す | データベースやファイルから商品情報を読み書きする |

要求と結果は、UI・Process・Dataの隣り合う層のMessengerを通ります。UIがデータベースを直接読んだり、Processが画面部品を操作したりはしません。各役割の具体的な通信経路は[Data Flow](data-flow.md)、CommanderとMessengerの境界は[Commander & Messenger](commander-messenger.md)で確認できます。

## 層と役割は別の軸

**層は「何に関する仕事か」**を表し、**役割は「その層の中で何をするか」**を表します。3つの役割を新しい層として積み重ねるのではなく、各層の仕事を呼び出しの整理、層間通信、実作業という観点で分けて考えます。

```text
役割＼層       UI                    Process                 Data
Commander     UI側の処理を選ぶ       検証や取得処理を選ぶ       読込・保存処理を選ぶ
Messenger     Processへ要求を送る     UI/Data間の要求を中継する  Processへ結果を返す
Processing    入力を解釈し画面表示     条件を検証し計算する       データを読み書きする
```

列は層、行は役割です。たとえば商品検索では、「キーワードを画面に表示する形へ整える」はUIのProcessing、「検索条件を検証する」はProcessのProcessing、「商品をデータベースから読む」はDataのProcessingにあたります。それぞれの層のCommanderは次の処理を選び、Messengerは層を越える要求や結果を運びます。

この表と図は考え方を説明する例です。すべての層に同じ名前のクラスやファイルを作ることを求めてはいません。物理的な分割方法は言語やプロジェクトの事情に合わせられます。

## 3つの層

- **UI Layer**: 入力受付、画面状態、表示形式、描画など、利用者とのやり取りを担当します。
- **Process Layer**: アプリケーションのルール、入力の検証、計算、処理の結果を決めます。画面の色やデータベースの保存形式には依存しません。
- **Data Layer**: データベース、ファイル、外部データなどの取得・保存・読み込み・変換を担当します。画面表示やアプリケーションのルールは判断しません。

層を分けることで、たとえば画面や保存先を変更するときに、検索や計算のルールまで一緒に書き換えずに済みます。

## 3つの役割

- **Commander**は、その層で次に呼ぶ処理を選び、処理の順序を組み立てます。計算、描画、保存などの実作業は担当しません。
- **Messenger**は、隣り合う層の間で要求と結果を運びます。業務上の判断や表示方法は決めません。
- **Processing**は、その層に属する実作業を行います。例として、UIでは入力の解釈や表示、Processでは検証や計算、Dataでは読み書きがあります。

実際の配置や禁止事項などの規範は、[Layer Specification](../specification/layer-spec.md)、[Commander Specification](../specification/commander-spec.md)、[Messenger Specification](../specification/messenger-spec.md)に定義されています。

## UIが表示方法を決める

Processが検索結果として商品名や価格を返した後、価格を「¥1,200」と表示するか、商品を行やカードのどちらで見せるかはUIが決めます。Processは画面の色、文字の書式、配置を知る必要がありません。反対に、UIは検索条件や価格計算のルールを担当しません。

UPDは、特定の設計パターンに由来する名前を必須のクラス名として指定しません。必要な役割と通信経路を保てるなら、言語やフレームワークに自然な構成を選べます。
