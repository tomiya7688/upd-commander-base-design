# Responsibility Check Rules

この文書は、UPD Commander Checker が責務過多と責務単位の配置を判定するときの共通基準を定義します。

## UPD401: 責務単位が過大

`UPD401` は、1つの責務単位が大きくなりすぎて分割候補になっていることを示す `warning` です。

これは「250行を超えたら必ず複数責務である」と断定する規則ではありません。UPD Commander 設計では大きな責務単位を分割候補として早めに可視化できることを重視するため、保守的な警告境界として扱います。

### 共通しきい値

- source span: **250行まで**
- responsibility-bearing methods: **12個まで**
- **251行以上**、または **13メソッド以上**で `UPD401` warning

行数とメソッド数のどちらか一方が境界を超えれば警告対象です。

### 責務単位

ASTで型を認識できる実装は、ファイル全体より型を優先して判定します。

- Python: class
- Go: named type + receiver methods を1責務単位として集約
- C++: class / struct
- C#: class / struct / record などの type declaration

言語構造上、責務単位を型として確定できないソースだけは file/module を近似責務単位として扱って構いません。この場合、メッセージに file/module approximation であることが分かる表現を用います。

### 行数の数え方

ASTで責務単位の開始行と終了行を取得できる場合は、その source span を使用します。空行やコメントだけを言語ごとに別計算して基準を変えてはいけません。

Goではメソッドが型宣言の外側に書かれるため、named type declaration の source span と、その型をreceiverに持つ各method declarationのsource spanを合計します。

### メソッド数の数え方

責務単位へ直接所属する通常のmethod declarationを数えます。

- コンストラクタは含めない
- property/accessor はmethod数へ含めない
- nested type 内部のmethodは外側typeへ加算しない

言語に通常のmethod概念がない場合のみ、最も近い callable member を使用できます。

## UPD402: 1ファイルに複数の主要責務型

`UPD402` は、1ファイルに複数の responsibility-bearing type/class が存在することを示す `warning` です。

データ保持だけを目的とし、業務的な振る舞いを持たない型は `UPD402` の主要責務型には数えません。データ専用型の配置は `UPD403/UPD404` で別に扱います。

## UPD403: 複数のデータ専用型が同居

1ファイルに複数のデータ専用型が存在する場合は `attention` とします。

データ専用型は、DTO、Contract、Value Container、設定値保持用型など、主目的がデータ保持であり、業務的な処理を持たない型を指します。

同一ファイル内だけで利用される場合は責務分離上の重大問題とはしませんが、型名から定義ファイルを予測しづらくなるため、配置改善候補として可視化します。

## UPD404: 同居するデータ専用型の外部参照

`UPD403` の対象となるデータ専用型が、別ファイルから実際に参照されていることを静的解析で確認できた場合は `warning` に引き上げ、`UPD404` を報告します。

単に public/exported/internal 等で外部参照可能なだけでは `UPD404` にしてはいけません。別ファイルのASTまたは同等の構文解析結果から、対象型名への参照を確認した場合だけ報告します。

この規則の目的は、利用側から定義場所を追跡しやすくすることです。外部参照されるデータ型は、原則として型名と対応する独立ファイルへ分離することを推奨します。

### 優先順位

- 同一ファイル内だけで完結: `UPD403` attention
- 別ファイルから参照: `UPD404` warning
- `UPD404` が成立する型について、同じ型に `UPD403` を重複表示する必要はありません

## UPD401との関係

`UPD401` は「1責務単位そのものが過大」を示します。

`UPD402` は「1ファイルに複数の責務を持つ主要type/classが存在する」を示します。

`UPD403/UPD404` は「データ専用型の配置と探索性」を示します。

同じファイルで異なる観点の規則が成立する場合は、それぞれ報告して構いません。

## Checker実装要件

各言語Checkerは、この文書の250行 / 12メソッドを共通の基準値として実装しなければなりません。

また `UPD403/UPD404` は、言語ごとの可視性指定ではなく、実際の構文上の参照を基準に判定しなければなりません。

しきい値や責務配置ルールを変更する場合は、先にこの文書を変更し、同一変更で全言語実装と境界テストを同期します。
